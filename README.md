# Hina Discord Bot

소라사키 히나를 연기하는 비공식 한국어 Discord 봇입니다. Python 3.11+, discord.py,
OpenAI Responses API, SQLite를 사용합니다. 프롬프트 교체와 소규모 단일 인스턴스 운영을
전제로 한 첫 버전입니다. 공식 서비스나 공식 대사 재현물은 아닙니다.

## 구현 상태

- 직접 멘션, 답장 핑, 메시지 시작의 `히나야` 호출에 반응해 **일반 채널 메시지**를 보내요.
- 서버·사용자·채널별 최근 대화와 자동 장기 요약을 SQLite에 저장해요.
- 같은 사용자의 공개 서버 대화는 DM에서 참고하고, DM 기억은 서버로 전달하지 않아요.
- 개인 메모, 관리자용 서버 공통 메모, 기억 확인·삭제 명령을 제공해요.
- API 시간 제한·재시도, 사용자별 쿨다운, 동시 요청 제한, 출력 분할, 자동 멘션 억제를 적용해요.
- Docker Compose 실행 설정과 GitHub Actions 테스트를 포함해요.

**외부 연결 상태:** 이 초안을 만든 환경에서 OpenAI 키 발급 요청이 거부되어 키가 저장되지
않았어요. Discord 토큰도 아직 설정되지 않았어요.
GitHub 저장소: https://github.com/sendoru/hina-discord-bot
실제 Discord 접속과 유료 OpenAI 요청은 실행하지 않았어요.

## 빠른 실행

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env.local
# 로컬 편집기에서 .env.local의 OPENAI_API_KEY와 DISCORD_TOKEN을 입력하세요.
chmod 600 .env.local
hina-bot
```

프로젝트 루트에서 실행해 주세요. 운영체제 환경 변수가 `.env.local`, `.env`보다 우선해요.
키는 소스에 넣지 않으며 `.env.local`, 데이터베이스, 대화 내용은 Git에서 제외해요.
`.env.local`을 Docker 이미지에도 포함하지 않아요.

Discord Developer Portal에서 애플리케이션과 Bot을 만들고, Bot 설정의 **Message Content
Intent**를 켜 주세요. `히나야`처럼 멘션 없는 호출을 읽으려면 필요해요.
서버에 초대할 때 `bot` scope와 `View Channels`, `Send Messages`, `Read Message History`를
허용해 주세요. 스레드에서도 사용하려면 `Send Messages in Threads`도 필요해요.
관리자 권한 전체를 줄 필요는 없어요. DM은 사용자의 서버 개인정보/DM 수신 설정에도 영향을 받아요.
이 버전은 일반 봇 초대 방식이며 사용자 설치 앱이나 실제 슬래시 명령을 사용하지 않아요.

```bash
docker compose up -d --build
docker compose logs -f
```

Compose는 named volume에 SQLite를 보존해요. `docker compose down -v`는 기억도 삭제해요.
데이터베이스 파일을 공유하는 여러 봇 프로세스를 동시에 실행하지 마세요.

## 호출 규칙

| 입력 | 기본 동작 |
| --- | --- |
| `@히나 오늘 어땠어?` | 응답해요. |
| 히나 메시지에 답장, 답장 핑 켜짐 | 응답해요. |
| 히나 메시지에 답장, 답장 핑 꺼짐 | 다른 호출 조건이 없으면 응답하지 않아요. |
| `히나야 오늘 어땠어?` | 응답해요. 앞쪽 공백은 허용해요. |
| `오늘 히나야라고 불렀어` | 응답하지 않아요. |
| DM의 일반 메시지 | 기본적으로 응답하지 않아요. `DM_ALWAYS_REPLY=true`로 바꿀 수 있어요. |
| 봇·웹훅·자기 자신의 메시지 | 응답하지 않아요. |

접두어는 문자열 `히나야`로 시작하는지 판별하므로 `히나야안녕`도 호출이에요.
Discord가 전달한 `message.mentions`를 검사하며, 답장 참조가 있다는 이유만으로 핑을
추정하지 않아요. 출력에는 `message.reply()`나 메시지 reference를 사용하지 않아요.
첨부파일·이미지·링크의 실제 내용, 답장 대상 원문을 별도로 읽지 않아요.
호출된 현재 텍스트와 이 봇이 저장한 대화만 문맥으로 사용해요.

## 기억의 방향

| 출처 | 서버 A 답변 | 서버 B 답변 | 같은 사용자의 DM 답변 |
| --- | --- | --- | --- |
| 서버 A의 해당 채널·해당 사용자 대화 | 사용해요. | 사용하지 않아요. | 공개 조건을 충족하면 참고해요. |
| 서버 A의 다른 사용자 대화 | 사용하지 않아요. | 사용하지 않아요. | 사용하지 않아요. |
| 서버 A의 비공개 채널 대화 | 원래 채널·사용자에게만 사용해요. | 사용하지 않아요. | 사용하지 않아요. |
| 서버 A의 개인 메모 | 같은 사용자에 한해 서버 A의 채널 간 공유해요. | 사용하지 않아요. | 자동으로 가져오지 않아요. |
| 관리자 지정 서버 A 공통 메모 | 서버 A의 모든 사용자에게 적용해요. | 사용하지 않아요. | 자동으로 가져오지 않아요. |
| 사용자의 DM 대화 | 사용하지 않아요. | 사용하지 않아요. | 해당 사용자에게만 사용해요. |

공개 여부는 '서버 채널'이라는 이유로 가정하지 않아요. **메시지를 저장할 당시와 DM에서
조회할 당시 모두** `@everyone`의 채널 보기·메시지 기록 보기 권한을 충족하는 일반 텍스트
채널만 허용해요. DM 조회 시 해당 사용자의 현재 서버 가입 상태를 REST로 확인하고,
사용자 자신의 채널 권한도 확인해요. 확인 실패·서버 탈퇴·채널 삭제 시 가져오지 않아요.
채널 권한은 Discord Gateway가 갱신한 캐시를 기준으로 하므로 변경 전파에 짧은 지연이
있을 수 있어요. 첫 버전에서는 공개 스레드와 포럼까지 포함해 모든 스레드를 제외해요.

한 채널의 대화에 비공개 문맥이 섞였으면 그 이후 자동 요약과 턴도 DM 내보내기에서
보수적으로 제외해요. 채널을 공개로 바꿔 과거 비공개 문맥이 유출되는 것을 막기 위한
처리예요. 해당 사용자의 기억을 삭제하면 새 대화부터 다시 판별해요.

DM에서는 최근 활동 순으로 최대 30개 출처를 검사하고, 접근 가능한 최대 4개 채널의 요약과
최근 사용자 발화 2개씩을 참고해요. 임베딩 검색이나 모든 서버 기록 검색은 아직 없어요.
공개 출처를 DM 요약에 직접 복사하지 않고 응답 시에만 조회해요.
`PUBLIC_SERVER_MEMORY_IN_DM=false`로 이 참조 자체를 끌 수 있어요.

**삭제와 권한 변경의 한계:** 원본 삭제·비공개 전환은 이후 원본 조회를 막지만, 이미 전송한
DM 답변과 그 답변에 이어진 DM 대화까지 소급 삭제하지는 않아요. 모델이 공개 정보에서
파생한 내용을 DM 답변에 쓸 수 있으므로 완전한 철회가 필요하면 DM 기억도 초기화해 주세요.
서버에서 대화한 내용을 DM에서 참고한다는 사실을 서버 이용자에게 안내하는 것이 좋아요.

## 자동 요약과 저장 범위

일반 응답을 Discord에 성공적으로 보낸 뒤 사용자 입력과 봇 응답을 한 턴으로 저장해요.
기본적으로 8턴마다 기존 요약과 아직 요약하지 않은 턴을 합쳐 장기 요약을 갱신해요.
최근 원문 12턴과 길이가 제한된 요약을 함께 사용하므로, 오래된 대화는 원문이 아닌
요약 형태로 남아요. 요약은 재시작해도 유지되지만 모든 사실을 완벽하게 기억하지는 못해요.

자동 요약 실패는 대화 응답을 취소하지 않고 다음 턴에 다시 시도해요. 요약 API가 오래
실패하면 원문 보관 상한을 넘긴 과거 정보는 유실될 수 있어요. 요약은 사실 검증 수단이
아니며 오기억이 생길 수 있어요. 중요 사실은 `/메모`로 명시할 수 있어요.
원문은 대화별 턴 수 제한을 적용하며 시간 기반 자동 만료는 아직 없어요.
API에 입력되는 문맥과 출력 크기도 제한해 비용이 대화 길이에 따라 무한히 증가하지 않게 해요.
기본 모델은 `gpt-4.1-mini`이며 `.env.local`에서 응답·요약 모델을 각각 바꿀 수 있어요.

OpenAI 요청은 `store=False`를 사용해요. 이것이 OpenAI의 모든 보관 정책에서 제외된다는
뜻은 아니에요. 호출된 대화·메모·관련 요약은 OpenAI로 전송되므로 봇 이용 안내에 반영해 주세요.
호출되지 않은 일반 채팅은 저장하거나 API에 보내지 않아요. 일반 로그에는 대화 본문,
토큰, 프롬프트, SDK 오류 원문을 남기지 않아요. SQLite와 운영자의 백업은 평문일 수 있어요.

## 기억 관리

아래 명령은 **실제 Discord 슬래시 명령이 아니라**, `히나야`나 멘션 뒤에 붙이는 텍스트예요.

```text
히나야 /도움말
히나야 /기억
히나야 /메모 나를 민철이라고 불러 줘. 설명은 한국어로 부탁해.
히나야 /메모삭제
히나야 /기억삭제 확인
히나야 /서버기억
히나야 /서버메모 이 서버의 스터디 모임은 매주 토요일 저녁이야.
히나야 /서버메모삭제
```

`/메모`는 기존 메모를 교체해요. 서버 개인 메모는 같은 서버의 다른 채널에서도 쓰므로
채널 한정 비밀을 적지 마세요. `/서버메모`는 서버 관리 권한을 가진 사람이 작성하며
모든 서버 구성원에게 사용될 공통 설정만 적어 주세요. 메모의 최대 길이는 1500자예요.
관리 명령은 모델에 보내지 않으며 일반 대화 기록에도 넣지 않아요.

`/기억삭제 확인`은 실행한 서버의 **해당 사용자 전체 채널** 기록·요약·개인 메모를
삭제해요. 다른 서버, 다른 사용자, DM, 서버 공통 메모는 지우지 않아요.
DM에서 실행하면 자신의 DM 기억만 삭제해요. 서버 기억과 DM 기억을 함께 초기화하려면
각각 실행해 주세요. 서버 공통 메모는 관리자가 `/서버메모삭제`로 삭제할 수 있어요.
Discord에 이미 전송된 메시지, 파일시스템 백업, API 제공자의 보관 데이터는 별도로 남을 수 있어요.

## 프롬프트 교체

기본 캐릭터 지침은 `src/hina_bot/prompts/hina.md`예요. 신뢰와 책임감, 담백한 말투,
상황별 반응, 관계의 점진성, 없는 기억을 만들지 않는 규칙과 창작 예시를 포함해요.
정식 프롬프트를 별도 UTF-8 파일로 저장하고 `CHARACTER_PROMPT_PATH`에 경로를 지정한 뒤
봇을 재시작하면 돼요. 파일 경로는 실행 디렉터리 기준이며 절대 경로도 가능해요.
Docker에서는 해당 파일을 읽기 전용으로 마운트하거나 이미지를 다시 빌드해 주세요.

운영·권한 지침은 `llm.py`의 `POLICY`, 요약 지침은 `SUMMARY_POLICY`로 분리해 두었어요.
메모나 사용자 표시 이름은 시스템 프롬프트가 아닌 사용자 역할 참고 데이터로 전달해요.
다만 프롬프트 인젝션을 문장만으로 완전히 막을 수는 없으므로, 모델에 타인 기억 조회나
DB 수정 도구 자체를 제공하지 않아요. 접근 경계와 삭제 권한은 Python 코드에서 처리해요.

## 테스트와 제한

```bash
python -m pip install -e '.[dev]'
ruff check .
pytest -q
# 외부 패키지 설치가 어려운 환경에서도 핵심 테스트를 실행할 수 있어요.
PYTHONPATH=src python -m unittest discover -s tests -v
```

SDK·Discord 어댑터 테스트는 실제 네트워크 대신 mock transport와 메시지 객체를 사용해요.
의존성이 없으면 해당 테스트는 skip되고, 호출 규칙·SQLite 테스트는 표준 라이브러리만으로
실행돼요. GitHub Actions는 의존성을 설치한 뒤 전체 테스트를 수행하도록 설정했어요.

이 초안을 만든 환경에서 Python 3.12로 핵심 테스트와 SDK·Discord 어댑터 테스트
**총 23개를 통과**했고, Ruff 검사와 Python 문법 컴파일을 확인했어요.
컨테이너 빌드, Python 3.11/3.13 실행, 실제 로그인·응답 품질 검증은 아직 하지 못했어요.

현재는 단일 프로세스용이에요. 여러 인스턴스의 분산 락, 비용의 월별 강제 상한,
메시지 수정/삭제 이벤트의 기억 반영, 음성·이미지, 전체 채널의 다인 대화 문맥은
구현하지 않았어요. 같은 채널에서도 사용자마다 대화가 나뉘어요.
응답 도중 프로세스가 종료되거나 분할 전송이 부분 실패하면 완전한 exactly-once 전달은
보장하지 못해요. 저장된 최근 메시지 ID의 중복 처리는 억제해요.
